## 2. Itemized Correction Log

### Item 1: Motorcomm Switch Register `0x8000c` Bitfields & Dual-Conduit Control
- **Previous Claim:** Bit 0 (tag enable), Bits 2:1 (conduit selection), Bit 4 (dual-conduit toggle). Values `0x00001100` and `0x00001104`.
- **Previous Classification:** `SOURCE_VERIFIED`
- **Revised Claim:** Upstream Linux kernel driver (`drivers/net/dsa/yt921x.c`) defines:
  - Bit 15: `YT921X_EXT_CPU_PORT_TAG_EN` (Tag Enable)
  - Bit 14: `YT921X_EXT_CPU_PORT_PORT_EN` (CPU Port Enable)
  - Bits 3:0: `YT921X_EXT_CPU_PORT_PORT_MASK` (Designated CPU Port index)
  - Standard values: `0x0000c008` (Port 8 CPU), `0x0000c004` (Port 4 CPU).
  - There is **no bit-4 dual-conduit toggle** in register `0x8000c`. Dual-conduit is achieved via switch VLAN/port isolation matrices (`PORT_MEM` / `VLAN_MEM`) and dual CPU port declarations in the Device Tree.
- **Revised Classification:** **`SOURCE_VERIFIED`**
- **Technical Rationale:** Verified directly in Linux kernel mainline `yt921x.c` source code (lines 35-40).

### Item 2: Winbond W25N01GW SPI NAND Flash ECC Requirements
- **Previous Claim:** Mandatory 8-bit controller BCH ECC (`nand-ecc-strength = 8`, `nand-ecc-step-size = 512`). Any mismatch causes rootfs corruption.
- **Previous Classification:** `SOURCE_VERIFIED`
- **Revised Claim:** Official Winbond W25N01GW datasheet Rev G and Linux kernel driver `drivers/mtd/nand/spi/winbond.c` establish that the chip features an **internal 1-bit on-die ECC engine per 512 bytes** (`NAND_ECCREQ(1, 512)`). Controller-level 8-bit BCH ECC is unproven on IPQ5018 SPI-NAND driver and has been retracted.
- **Revised Classification:** **`SOURCE_VERIFIED`** (for 1-bit on-die ECC); **`REPORTED_UNVERIFIED`** (for controller ECC override).
- **Technical Rationale:** Official Winbond W25N01GW component datasheet and upstream Linux `winbond.c` registration macro.

### Item 3: MTD Partition Map & Dynamic Runtime Enumeration
- **Previous Claim:** Hardcoded integer MTD indices (`mtd7 = 0:ART`, `mtd11 = 0:APPSBL`, `mtd12 = 0:APPSBL_1`, `mtd13 = rootfs`).
- **Previous Classification:** `SOURCE_VERIFIED`
- **Revised Claim:** Formally distinguished **Partition Labels**, **Physical Flash Offsets**, and **Dynamic Runtime MTD Enumeration**. Enshan forum logs demonstrate that runtime indices vary across firmware builds (e.g. `mtd13` reported as ART, APPSBL at `mtd11` or `mtd12`). Scripts and documentation must resolve partitions strictly by label (`find_mtd_part`) rather than fixed `/dev/mtdX` indices.
- **Revised Classification:** **`REPORTED_UNVERIFIED / DEVICE_DEPENDENT`** (for integer indices); **`SOURCE_VERIFIED`** (for MIBIB partition labels).
- **Technical Rationale:** Linux kernel MTD subsystem dynamic probe ordering.

### Item 4: Non-UART Recovery Protocols & Safety Assertions
- **Previous Claim:** "100% unbrickable recovery" via stock TFTP beacon (`192.168.31.1` -> `192.168.31.100`, `test.bin`) and autonomous bootcounter failover after 3 failures.
- **Previous Classification:** `SOURCE_VERIFIED`
- **Revised Claim:** Separated four independent recovery channels:
  1. Stock Xiaomi TFTP Recovery Tool (`REPORTED_UNVERIFIED` — packet exchange unverified).
  2. U-Boot HTTP Web Failsafe Recovery (`REPORTED_UNVERIFIED` — reported at `192.168.1.1` in modified bootloaders).
  3. UART Serial Console (`SOURCE_VERIFIED`, but user has no UART adapter).
  4. Dual-Rootfs Bootcounter Failover (`INFERRED / REPORTED_UNVERIFIED` — unverified via serial boot logs on this unit).
  The "100% recovery safety" assertion is completely retracted. Flash authorization remains strictly **`NO-GO`**.
- **Revised Classification:** **`REPORTED_UNVERIFIED`** / **`INFERRED`**
- **Technical Rationale:** Lack of empirical packet captures and lack of serial boot log verification on the physical device.

### Item 5: GPIO 39 / 37 Switch Cold-Boot Conflict & Timing
- **Previous Claim:** Invented 100 ms stabilization delay (`reset-deassert-us = <100000>`) and pre-probe MDIO bus priming sequence.
- **Previous Classification:** `SOURCE_VERIFIED` / Engineering resolution
- **Revised Claim:** Retracted invented timings. Re-grounded baseline strictly in David Yang's upstream verified DTS timing:
  ```dts
  reset-gpios = <&tlmm 39 GPIO_ACTIVE_LOW>;
  reset-assert-us = <10000>;
  reset-deassert-us = <50000>;
  ```
  The conflict between upstream active-low reset and community LAN LDO power enable + MDIO clock burst is maintained as **`CONFLICT_UNRESOLVED`** pending physical oscilloscope signal probing.
- **Revised Classification:** **`CONFLICT_UNRESOLVED`**
- **Technical Rationale:** Adherence to verified upstream tree; elimination of speculative driver delays.

### Item 6: QCN6102 Wi-Fi 6 HE160 & DFS Availability
- **Previous Claim:** Extracting calibration data at offset `0x26800` in `0:ART` automatically ensures HE160 160MHz DFS operation.
- **Previous Classification:** `SOURCE_VERIFIED`
- **Revised Claim:** Disambiguated physical chip (**QCN6102**) from the upstream driver firmware path (**`qcn6122`**). Clarified that calibration data contains only RF power curves. Full 160 MHz DFS operation requires kernel radar detection (`ath11k_dfs`) and regulatory compliance in `wireless-regdb`.
- **Revised Classification:** **`SOURCE_VERIFIED`** (for caldata offsets); **`REPORTED_UNVERIFIED`** (for HE160 DFS operation).
- **Technical Rationale:** Regulatory and mac80211 radar detection prerequisites independent of flash caldata.

### Item 7: Qualcomm NSS Parser Behavior & Tag Length
- **Previous Claim:** Motorcomm switch inserts 4-byte DSA tags; NSS microcode drops 100% of packets; invented 25-35 MB memory leak numbers.
- **Previous Classification:** `SOURCE_VERIFIED`
- **Revised Claim:** Motorcomm switch inserts **8-byte DSA tags** (TPID `0x9988` + 6B payload). Unrecognized EtherType prevents ECM hardware flowtable matching, but exact firmware drop vs slow-path diversion is unmeasured. Memory leak reports on 256MB devices are retained as unquantified community reports.
- **Revised Classification:** **`INFERRED`** (for parser behavior); **`REPORTED_UNVERIFIED`** (for memory retention).
- **Technical Rationale:** Motorcomm `tag_yt921x.c` 8-byte structure; elimination of unmeasured memory leak claims.
